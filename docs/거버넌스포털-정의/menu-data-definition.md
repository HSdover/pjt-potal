# 메뉴별 데이터 정의

작성일: 2026-06-08

이 문서는 현재 프로젝트 메뉴(router 기준)에 어떤 데이터가 들어가야 하는지를 증권사 예시 데이터로 구체화한다.
정의가 어려운 가장 큰 이유는 메뉴별 데이터를 따로 보는 것이 아니라 마스터 엔티티가 먼저 안 잡혀 있기 때문이다.

관련 문서:

- `ai-data-governance-overview.md`: 본 프로젝트의 본질과 비유 중심 설명
- `gold-metadata-lineage.md`: Gold 메타 모델과 리니지 정의
- `portal-screens.md`: 거버넌스 포털 5개 핵심 화면 설계 (재정의 전 기준)
- `../governance/screen-domain-template.md`: 기능목록 엑셀 기준 화면 도메인/템플릿 분류

## 1. 먼저 잡아야 할 마스터 엔티티 (모든 메뉴가 공유)

| 엔티티 | 무엇을 | 식별자 예시 |
|---|---|---|
| 데이터셋 (Dataset) | Gold 자산 = AI가 사용 가능한 데이터 단위 | `DS-FIN-20260847` |
| 메타 (Meta) | 데이터셋의 메타데이터 레코드 | `MT-FIN-20260847` |
| AI 에이전트 (Agent) | 챗봇/AI 앱 | `AGT-FIN-CHATBOT` |
| 파이프라인 (Pipeline) | Dataiku Flow 1개 | `PIPE-FIN-Q-REPORT` |
| 신청 (Request) | 매핑/배포/권한 신청 1건 | `REQ-2026-001234` |
| 사용자 (User) | SAML로 인증된 사용자 | `USR-hong.gildong` |
| 도메인 (Domain) | 업무 분류 | 재무, 리스크, 상품, CRM, AML |

이 7개 엔티티가 모든 메뉴에 등장하는 공통 데이터다.

## 2. 메뉴별 데이터 정의

#### 검색구분 (현재 6종) 사용 방식

| 검색구분 | 검색 대상 필드 |
|---|---|
| 업무 | 메타명, 도메인, 비즈니스용어, 업무설명 |

**정형 자산 (예: 종목코드마스터)**

| 탭 | 필드 예시 |
|---|---|
| 기본정보 | 메타ID, 메타명, 도메인=상품, 자산유형=정형, 원천=매매ADB, 소유자=상품팀, 보안등급=내부, 보존=10년, 적재주기=일배치 |

| 리니지 (추가 권장) | "매매시스템 → STOCK_MASTER 테이블 → ADB 적재" |
| 사용현황 (추가 권장) | 참조 AI에이전트: 3개, 일평균 호출: 12,400회 |

**반정형 자산 (예: 경영보고서) — Gold**

| 탭 | 필드 예시 |
|---|---|
| 기본정보 | 메타명=2026Q3경영보고서, 도메인=재무, 소유자=홍길동, 등급=대외비, MNPI=Y |
| 청킹/임베딩 (추가) | 청크전략=semantic, 청크크기=512토큰, 청크수=87, 임베딩=cohere v3, 벡터DB=Oracle 23ai FIN_QUARTERLY |

| 리니지 (추가) | 그래프: PDF → Silver → Gold → 청크 87 → Vector → 재무챗봇 |
| 사용현황 (추가) | 사용 챗봇: 재무챗봇/임원리포트봇, 30일 인용: 421회, 평균 점수: 0.87 |
| 청크목록 (추가) | CHK-0001 ~ CHK-0087 (페이지/토큰수/인용수) |

**파일 자산 (예: 리스크 정책)**

| 탭 | 필드 예시 |
|---|---|
| 기본정보 | 파일명, 확장자, 크기, 페이지수, 작성자, 등록일 |

### 2.4 AI데이터관리 > 데이터 매쉬

#### 화면 목적 권장안

리니지 시각화 + 도메인별 데이터 토폴로지 통합 화면.

증권사처럼 도메인이 명확한 조직에서는, 도메인별로 어떤 데이터셋이 있고 그들이 어떻게 연결되는지를 한눈에 보여주는 화면이 매우 가치 있다.

#### 상단: 도메인 토폴로지 맵

```text
       [재무]              [리스크]            [상품]
        │                    │                  │
   ┌────┴────┐         ┌─────┴────┐       ┌────┴────┐
   │ 23개    │         │ 12개     │       │ 47개    │
   │ Gold    │         │ Gold     │       │ Gold    │
   └─────────┘         └──────────┘       └─────────┘
        │                    │                  │
        └────────────┬───────┴──────────────────┘
                     ▼
              [재무챗봇] [임원봇]
              [리스크봇] [CS봇]
```

#### 하단: 리니지 그래프 (자산 선택 시)

선택한 Gold 자산의 풀 리니지:

```text
원본PDF
  → BRZ-20260847
    → SLV-20260847 (Dataiku PARSE_PDF_V3)
      → GLD-20260847 (Dataiku CHUNK_FIN_V2)
        → Chunks 87개
          → Vector Index FIN_QUARTERLY
            → 재무챗봇 (8,231건 응답)
            → 임원봇 (1,247건 응답)
```

#### 데이터 예시

```yaml
domain_view:
  재무:
    gold_count: 23
    agents: [재무챗봇, 임원리포트봇]
    classification_mix: {공개: 5, 내부: 8, 대외비: 8, MNPI: 2}
    monthly_citations: 8231
  리스크:
    gold_count: 12
    agents: [리스크챗봇]
    classification_mix: {내부: 7, 대외비: 5}
    monthly_citations: 1203
```

#### 필터/뷰

- 도메인별 / 에이전트별 / 보안등급별
- 노드 클릭 → 메타관리 상세로 점프
- 엣지 클릭 → Dataiku Recipe 상세

### 2.12 시스템 관리 > 권한관리 (구현됨)

#### 화면 목적

IAM/AD에서 내려오는 역할·그룹·사용자 기준으로 포털의 메뉴, 화면, CRUD, 다운로드, 업로드 권한을 관리한다.

#### 기본 IAM 역할

| IAM 역할 | 내부 코드 | 주요 권한 |
|---|---|---|
| 관리자 | `ADMIN` | 전체 메뉴, 권한관리, 배치 관리 |
| AI 에이전트관리자 | `AI_AGENT_ADMIN` | AI 데이터, 신청관리, 대시보드, 공지사항 |
| 데이터 관리자 | `DATA_ADMIN` | 메타데이터, 파이프라인, DP뷰어, 데이터 반입 |

#### DB 테이블

| 테이블 | 설명 |
|---|---|
| `portal_permission` | 포털 내부 권한 코드 정의 |
| `portal_iam_role` | IAM 역할과 외부 IAM/AD 그룹명 매핑 |
| `portal_permission_assignment` | IAM 역할, 그룹, 사용자별 권한 할당 |

#### 화면 구성

```text
[검색/선택 영역]
  대상 유형: IAM 역할 / 그룹 / 사용자
  대상 선택
  권한 키워드 검색
  그룹/사용자 대상 추가

[권한 그리드]
  허용 스위치
  권한 유형(SCREEN/CRUD/DOWNLOAD/UPLOAD/ADMIN)
  권한명
  권한코드
  대상
  동작
  설명
```

#### 운영 기준

- 운영에서 권한관리 화면 자체는 `PERMISSION_MANAGE` 권한이 필요하다.
- 로컬 계정은 `application-local.yml`의 권한 목록을 사용하므로 DB 권한 변경이 즉시 반영되지 않는다.
- SAML/IAM 사용자는 `portal_iam_role.external_group_name`과 SAML `roles`, `groups`, `memberOf` 값을 매칭해 권한을 계산한다.
- 상세 기준은 `../permission-management-guide.md`를 따른다.

## 4. 데이터 정의 우선순위 (착수 순서 권장)

| 순서 | 정의할 데이터 | 이유 |
|---|---|---|
| 1 | 데이터셋(메타) | 모든 메뉴가 참조하는 마스터. 메타관리에서 이미 구현 진행 중 |
| 2 | AI 에이전트 | 데이터셋과 양대 마스터. 매핑/응답추적 기반 |
| 3 | 파이프라인 | Dataiku 메타 동기화 기반. 운영 단계 가시화 |
| 4 | 매핑 (Agent↔Dataset) | 거버넌스 핵심. 권한 모델의 출발점 |
| 5 | 신청-승인 | 위 3개가 정의된 뒤에 의미 있음 |
| 6 | 응답 로그 | 가장 마지막. RAG 앱 연동 필요 |
| 7 | 공지사항 | 단순 게시판, 가장 후순위 |

## 5. 핵심 정리

| 메뉴 | 이 메뉴의 본질 |
|---|---|
| 메타관리 | "무엇이 있는가" — 데이터셋 카탈로그 |
| 파이프라인목록 | "어떻게 만들어지는가" — Dataiku 가공 흐름 |
| AI에이전트 매핑 | "누가 무엇을 쓰는가" — 권한 매트릭스 |
| 데이터 매쉬 | "전체가 어떻게 연결되는가" — 토폴로지/리니지 |
| 신청관리 | "어떻게 변경되는가" — 거버넌스 워크플로우 |
| DP뷰어 | "가공이 제대로 됐는가" — 품질 검증 |
| 대시보드 | "전체 상태가 정상인가" — 종합 모니터링 |
| 공지사항 | "운영자가 알려야 할 것" — 커뮤니케이션 |

이 8개 문장이 각 메뉴의 존재 이유다. 정의가 어려울 때는 "이 메뉴는 어떤 질문에 답하는가" 한 줄로 줄여본 다음, 그 질문에 답하기 위한 데이터만 채우면 된다.
