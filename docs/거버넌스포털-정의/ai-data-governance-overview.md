# AI 데이터 거버넌스 개요

작성일: 2026-06-08

이 문서는 본 프로젝트의 본질과 구조를 처음 접하는 사람도 이해할 수 있도록 풀어쓴 개요다.
기술적 메타·리니지 정의는 `gold-metadata-lineage.md`, 화면 설계는 `portal-screens.md`를 참고한다.

## 1. 한 줄 요약

> 5개 솔루션업체가 가진 자료들을 AI가 잘 쓸 수 있도록 가공한 다음,
> 그 가공된 자료를 안전하게 관리하는 도서관(거버넌스 포털)을 만드는 일.

## 2. 비유로 시작

이 프로젝트를 "AI를 위한 도서관"이라고 생각하면 쉽다.

- 회사에는 PDF 보고서, 워드 문서, 이미지, 표 같은 자료가 잔뜩 있다.
- 사람은 이 자료를 열어서 읽으면 된다.
- 그런데 AI(챗봇)가 이 자료를 읽고 사람 질문에 답하려면, 자료를 "AI가 소화하기 좋은 형태"로 잘게 잘라서 정리해줘야 한다.
- 이 정리 작업을 도와주는 도구가 Dataiku라는 솔루션이고,
- 정리된 자료를 사람이 안심하고 관리/감독할 수 있게 보여주는 화면이 거버넌스 포털이다.

요리에 비유하면:

- 원재료(원본 PDF) → 손질된 재료(텍스트) → 요리 준비 완료된 재료(AI가 쓰기 좋은 조각들)
- 거버넌스 포털 = 주방 위생/재고/레시피를 관리하는 매니저

## 3. "5개 솔루션 DB"가 무슨 뜻인가

회사 안에는 보통 여러 시스템이 따로따로 굴러간다.

예: 영업 시스템, 고객 관리 시스템, 회계 시스템, 보고서 시스템, 인사 시스템 등

이 5개 시스템마다 자기 데이터를 따로 가지고 있고, 각각 다른 회사가 만든 솔루션 5개의 DB라고 보면 된다.

이 모든 데이터를 오라클 클라우드(OCI) 위에 ADB(Autonomous Database, 오라클이 알아서 관리해주는 똑똑한 DB)로 올려서 운영한다.
다행히 다 같은 오라클 클라우드 안에 있으니까 연결과 보안 문제는 단순해진다.

## 4. Bronze / Silver / Gold 가공 단계

자료를 한 번에 AI가 쓸 수 있는 형태로 만들 수는 없다. 단계를 나눠서 가공한다.
이걸 메달리언 아키텍처라고 부른다.

### Bronze (원본 그대로)

- "방금 받은 원본 상태"
- PDF 파일, 워드 문서, 이미지 그 자체
- 손대지 않은 날 것
- 예: `2026년_3분기_경영보고서.pdf`

### Silver (텍스트로 풀어놓은 상태)

- "원본에서 글자만 깔끔하게 뽑아낸 노트"
- PDF에서 글자만 추출해서 `.md`(마크다운, 정돈된 텍스트 파일)로 저장
- 표, 그림 설명도 텍스트로 변환
- 사람이 봐도 읽을 수 있는 상태

### Gold (AI가 바로 쓸 수 있는 상태)

- "AI가 검색하기 좋게 잘게 자르고 꼬리표를 단 카드 묶음"
- Silver 텍스트를 적당한 크기(예: 500 글자)로 잘게 자른다 → 청크(chunk)
- 각 조각마다 AI가 이해하는 숫자 코드(임베딩)를 붙인다
- 이러면 AI가 "이 질문과 비슷한 조각 5개 찾아줘"가 가능해진다

요리 비유로:

- Bronze = 통째로 산 무
- Silver = 껍질 깎고 씻은 무
- Gold = 깍둑썰기까지 끝나서 봉투에 담긴 무

## 5. 청킹·파싱 풀어보기

- 파싱(parsing): PDF 같은 파일에서 글자를 뽑아내는 일. "원본을 텍스트로 풀어쓴다"는 뜻.
- 청킹(chunking): 긴 텍스트를 적당한 크기로 자르는 일. AI는 한 번에 너무 긴 글을 못 본다.

이 두 작업이 Bronze→Silver, Silver→Gold의 핵심이다.

## 6. Dataiku와 거버넌스 포털의 관계

### Dataiku = 가공 공장

- 파싱/청킹/임베딩을 실제로 수행하는 도구
- 데이터 엔지니어가 여기서 작업한다
- "어떻게 가공할지" 레시피를 짜고 돌리는 곳

### 거버넌스 포털 = 도서관 관리실

- 가공된 결과물(Gold)을 관리/감독/검색하는 화면
- 현업, 감사팀, 보안팀, 임원이 보는 곳
- "어떤 자료가 어디에 있는지, 누가 책임지는지, 안전한지"를 보여준다

### 둘 사이 관계

```
원본 자료 → [Dataiku 공장] → 가공된 Gold 자료
                                    ↓
                          [거버넌스 포털 도서관]
                                    ↓
                            사람들이 보고 관리
```

- Dataiku는 만드는 곳, 포털은 관리하는 곳
- 두 시스템은 친구지 경쟁자가 아니다
- SoT(Source of Truth) 분담은 `gold-metadata-lineage.md` 참고

## 7. 메타데이터 = "데이터에 대한 설명서"

도서관 책으로 비유:

- 책 본문 = 데이터
- 책의 제목, 저자, 출판일, 분야, 책 번호, 누가 빌려갔는지 = 메타데이터

거버넌스 포털에서 관리할 메타데이터:

| 종류 | 도서관 비유 | 예시 |
|---|---|---|
| 기술 정보 | 책 두께, 페이지 수 | "이 Gold는 청크 87개, 모델 cohere v3로 만들어짐" |
| 운영 정보 | 언제 들어왔는지, 누가 정리했는지 | "어제 18:00에 자동 처리, 품질 점수 94점" |
| 거버넌스 정보 | 누가 빌릴 수 있는지, 보존 기간 | "대외비 등급, 재무팀만 열람, 10년 보존" |
| 사용 정보 | 얼마나 많이 빌려갔는지 | "이번 달 AI가 421번 인용함" |

## 8. 데이터 리니지 = "족보" 또는 "발자취"

- 이 데이터가 어디서 왔고(출처)
- 어디로 갔는지(사용처)
- 그 길을 따라갈 수 있게 만든 지도

### 가장 중요한 사용 예

회사 AI 챗봇이 답한다.

> 챗봇: "2026년 3분기 영업이익은 1,820억원입니다."

사장님이 묻는다.

> "이거 어디서 나온 숫자야? 진짜 맞아?"

이때 거버넌스 포털을 켜면:

```
챗봇 답변
   ↓ 추적
이 답에 쓰인 조각(청크) 4개
   ↓
조각이 속한 Gold 자료
   ↓
Gold의 원본인 Silver 텍스트
   ↓
Silver의 원본인 Bronze PDF
   ↓
"2026_Q3_경영보고서.pdf 87페이지" ← 여기서 나왔어요!
```

이게 이 프로젝트의 가장 중요한 가치다. AI가 한 말을 사람이 사후에 확인하고 책임질 수 있게 만드는 것.

## 9. 왜 "비즈니스 정의"는 우선순위가 아닌가

처음에는 "이 컬럼의 비즈니스 정의는 뭐냐, 누가 책임지냐" 같은 일반적인 데이터 거버넌스 얘기로 시작할 수 있다.
하지만 이건 사람이 일일이 입력해야 하는 일이라 시간이 어마어마하게 든다.

그래서 이 프로젝트는 방향을 좁혔다.

> 도메인/업무 정의는 우리 일이 아니다.
> 우리 일은 AI가 쓰기 좋은 데이터로 가공하는 파이프라인을 관리하는 것이다.

이렇게 좁히면:

- 사람이 입력해야 할 게 거의 없음 (대부분 Dataiku가 자동으로 메타 만들어준다)
- 핵심 가치(AI 답변 출처 추적)에 집중할 수 있다

## 10. 또 한 번 좁히기 — "Gold만 관리"

또 한 번 단순화했다.

> Bronze, Silver는 Dataiku한테 맡기자.
> 거버넌스 포털은 Gold만 관리한다.

이유:

- Bronze/Silver는 공장 내부 작업물이지 사람들이 매일 들여다볼 자료가 아니다
- AI가 실제로 사용하는 건 Gold
- 보안/등급/소유자 관리도 Gold 단위면 충분
- 관리 화면이 12개 → 5개로 축소

Bronze/Silver는 "이 Gold가 어떤 PDF에서 왔는지" 표시할 때 ID와 파일명만 보여주면 된다.
자세히 알고 싶으면 "Dataiku에서 보기" 링크로 점프하면 끝.

## 11. 한 줄 요약 (다시)

> 회사 자료를 AI가 쓸 수 있게 Dataiku로 가공하고(Bronze→Silver→Gold),
> 그 결과물(Gold)을 사람이 안전하게 관리하고,
> AI가 한 말이 어디에서 나왔는지 추적할 수 있게 해주는 포털을 만드는 일.

## 12. 용어 사전

| 용어 | 쉬운 풀이 |
|---|---|
| OCI | 오라클이 만든 클라우드 서비스 (AWS, Azure 같은 것) |
| ADB | 오라클이 알아서 백업/보안/튜닝 다 해주는 똑똑한 DB |
| OCI Data Catalog | 여러 DB의 메타 정보를 자동으로 긁어모아주는 도구 |
| Dataiku | 데이터 가공 작업을 시각적으로 짜는 솔루션 (공장) |
| 메타데이터 | 데이터에 대한 설명서 (도서관 책정보) |
| 리니지 | 데이터의 족보/발자취 (어디서 와서 어디로 갔나) |
| 파싱 | 원본 파일에서 글자만 뽑아내기 |
| 청킹 | 긴 텍스트를 적당히 잘게 자르기 |
| 청크(chunk) | 잘라낸 조각 하나 |
| 임베딩 | 텍스트 조각을 AI가 알아보는 숫자로 바꾸는 것 |
| 벡터 | 그 숫자 표현 자체 |
| RAG | AI가 답하기 전에 관련 자료를 먼저 찾아보고 답하는 방식 |
| MNPI | 미공개 중요정보 (외부에 절대 새면 안 되는 자료) |
| PII | 개인을 식별할 수 있는 정보 (이름/주민번호 등) |
| SoT | "이 정보의 진짜 원본은 어디냐"라는 합의된 기준 (Source of Truth) |
