# 운영환경 유틸/필수파일 체크리스트

## 기준 구조

현재 프로젝트의 운영 배포 기준은 아래 구조다.

```text
사용자
-> Nginx 80/443
   - frontend/dist 정적 파일 서빙
   - /api, /login, /saml2, /actuator 요청을 Spring Boot로 프록시
-> Spring Boot JAR
   - 127.0.0.1:18080
   - systemd 서비스로 실행
```

운영 서버에서 직접 소스를 빌드하는 방식은 우선순위가 낮다. 가능하면 개발 PC, 빌드 PC, CI에서 산출물을 만들고 운영 서버에는 산출물과 설정 파일만 올린다.

## 실제 준비 폴더

운영 준비 파일은 `C:\workspace\governance-portal-operational-kit` 아래에 용도별로 정리한다.

```text
C:\workspace\governance-portal-operational-kit\
  01-client-tools\                 # 작업 PC 설치 유틸
  02-release-package-template\      # 배포 zip 구성 템플릿
  03-server-config-templates\       # env, nginx, systemd, logrotate 템플릿
  04-security-files-placeholders\   # TLS, SAML, DB wallet, SSH key 자리
  05-checklists\                    # 업로드/서버명령/롤백 체크리스트
  06-downloads-needed\              # 다운로드 출처와 결과 로그
```

## 1. 작업 PC에 추가 준비할 유틸

`C:\workspace\util` 폴더 기준으로 파일 전송, SSH 접속, 압축/해제, 소스 관리, 빌드 실행, DB 접속, 문서 편집/비교 유틸은 이미 확보되어 추가 준비 목록에서 제외한다.

현재 추가로 검토할 유틸은 아래만 남긴다.

| 구분 | 유틸 | 용도 | 비고 |
|---|---|---|---|
| API 확인 | Postman 또는 사내 허용 API 테스트 도구 | SAML 적용 후 세션/API 확인 | 운영망에서는 브라우저와 curl만 허용될 수 있음 |
| OCI 관리 | OCI CLI | Object Storage, Compute, LB 확인 | 운영 권한/정책 확인 후 설치 |

이미 확보된 작업 PC 유틸:

| 구분 | 확보 파일 | 대체/충족 항목 |
|---|---|---|
| 파일 전송 | `FileZilla_3.70.5_win64_sponsored2-setup.exe` | FileZilla |
| SSH 접속 | `MobaXterm_Installer_v26.3.zip` | SSH/SFTP 터미널 |
| 압축/해제 | `BANDIZIP-SETUP-STD-X64.EXE` | 7-Zip 대체 |
| 소스 관리 | `Git-2.54.0-64-bit.exe` | Git for Windows |
| 빌드 실행 | `PowerShell-7.6.1-win-x64.msi` | PowerShell 7 |
| DB 접속 | `dbeaver-ce-26.0.5-windows-x86_64.exe` | DBeaver |
| 문서/편집 | `VSCodeUserSetup-x64-1.117.0.exe`, `npp.8.9.6.Installer.x64.exe` | VS Code, Notepad++ |
| 비교 | `WinMerge-2.16.56-x64-Setup.exe` | 설정/산출물 diff |
| 브라우저 | `ChromeSetup.exe` | 운영 화면 확인 |
| IDE | `idea-2026.1.1.exe` | 개발/소스 확인 |

파일 전송은 확보된 FileZilla 또는 MobaXterm의 SFTP를 사용한다.

```text
호스트: 운영 서버 public/private IP 또는 bastion 경유 주소
프로토콜: SFTP
포트: 22
계정: 배포 전용 계정
인증: SSH private key
```

## 2. 운영 서버에 필요한 기본 패키지

| 구분 | 패키지/서비스 | 용도 | 필수 여부 |
|---|---|---|---|
| Java | JDK/JRE 21 | Spring Boot JAR 실행 | 필수 |
| Web | Nginx | 프론트 정적 파일 서빙, API reverse proxy | 필수 |
| 서비스 관리 | systemd | 백엔드 서비스 등록/재시작 | 필수 |
| 방화벽 | firewalld | 80/443 허용, 18080 외부 차단 | 필수 |
| 시간 동기화 | chrony | SAML/인증서 시간 검증 안정화 | 필수 |
| 로그 관리 | logrotate | Nginx/애플리케이션 로그 순환 | 필수 |
| 점검 도구 | curl | health check | 필수 |
| 파일 도구 | unzip, tar, rsync | 배포 파일 해제/동기화 | 권장 |
| 편집기 | vim 또는 nano | 긴급 설정 확인 | 권장 |
| 네트워크 점검 | ss, lsof, telnet/nc | 포트/연결 확인 | 권장 |
| 보안 | SELinux 관련 도구 | SELinux enforcing 환경 대응 | 정책 확인 후 |

운영 서버에는 Node.js/npm, Gradle을 반드시 설치할 필요가 없다. 운영 서버에서 직접 빌드해야 하는 정책이면 그때만 Node.js와 Gradle wrapper 캐시를 준비한다.

## 3. 서버 디렉터리 기준

운영 서버에는 아래처럼 역할별 디렉터리를 분리한다.

```text
/opt/governance-portal/
  governance-portal-backend.jar
  releases/
  logs/
  config/

/var/www/governance-portal/
  index.html
  assets/

/etc/nginx/conf.d/
  governance-portal.conf

/etc/systemd/system/
  governance-portal.service
```

권한 기준:

```text
governance 계정: JAR 실행, 로그 쓰기
nginx 계정: 정적 파일 읽기
sudo 권한: systemd/nginx/firewall 작업에만 제한 부여
```

## 4. 운영 서버에 업로드할 필수 파일

| 파일/폴더 | 생성 위치 | 서버 위치 | 필수 여부 |
|---|---|---|---|
| `frontend/dist/**` | `frontend/dist` | `/var/www/governance-portal/` | 필수 |
| `governance-portal-backend.jar` | `backend/build/libs/` | `/opt/governance-portal/governance-portal-backend.jar` | 필수 |
| Nginx 설정 | `infra/nginx/governance-portal.conf` | `/etc/nginx/conf.d/governance-portal.conf` | 필수 |
| systemd 설정 | `infra/systemd/governance-portal.service` | `/etc/systemd/system/governance-portal.service` | 필수 |
| 운영 env 파일 | 별도 작성 | `/opt/governance-portal/config/governance-portal.env` | 필수 권장 |
| TLS 인증서/키 | 보안팀/인증서 담당 | `/etc/pki/tls/...` 또는 지정 경로 | 443 사용 시 필수 |
| SAML IdP metadata 또는 URL | IAM/KNOX 담당 | env 또는 지정 파일 | SAML 운영 시 필수 |
| DB 접속 정보 | DBA/운영 담당 | env 또는 보안 저장소 | 운영 DB 사용 시 필수 |
| Oracle Wallet | DBA/OCI 담당 | `/opt/governance-portal/config/wallet/` | ADB 사용 시 필수 |
| logrotate 설정 | 별도 작성 | `/etc/logrotate.d/governance-portal` | 권장 |
| 롤백용 이전 산출물 | 배포 시 보관 | `/opt/governance-portal/releases/` | 권장 |

운영 env 파일에는 민감정보가 들어가므로 Git에 커밋하지 않는다.

## 5. 운영 env 파일에 들어갈 주요 값

기본 템플릿은 프로젝트의 `infra/env/governance-portal.env.template`을 기준으로 한다.
운영 서버에는 `/opt/governance-portal/config/governance-portal.env`로 작성하고, 일반 배포 zip이나 Git에는 넣지 않는다.

예시:

```bash
SPRING_PROFILES_ACTIVE=saml,adb
SERVER_PORT=18080

GOVERNANCE_H2_CONSOLE_ENABLED=false
GOVERNANCE_SQL_INIT_MODE=never

# Spring Batch 메타테이블(BATCH_*)은 Oracle에서 자동 생성되지 않는다.
# 권장: DBA가 Spring Batch 공식 schema-oracle.sql로 BATCH_ 테이블을 선생성하고 아래는 never로 둔다.
GOVERNANCE_BATCH_SCHEMA_INITIALIZE=never

GOVERNANCE_DATASOURCE_URL=jdbc:oracle:thin:@//db-host:1521/service
GOVERNANCE_DATASOURCE_DRIVER=oracle.jdbc.OracleDriver
GOVERNANCE_DATASOURCE_USERNAME=appuser
GOVERNANCE_DATASOURCE_PASSWORD=change-me

GOVERNANCE_CACHE_TYPE=redis
GOVERNANCE_CACHE_REDIS_TTL=300s
GOVERNANCE_CACHE_REDIS_KEY_PREFIX=governance:
GOVERNANCE_REDIS_HOST=redis-host
GOVERNANCE_REDIS_PORT=6379
GOVERNANCE_REDIS_DATABASE=0
GOVERNANCE_REDIS_PASSWORD=
GOVERNANCE_REDIS_TIMEOUT=2s
GOVERNANCE_REDIS_HEALTH_ENABLED=true

GOVERNANCE_EXTERNAL_API_CONNECT_TIMEOUT=3s
GOVERNANCE_EXTERNAL_API_READ_TIMEOUT=10s
GOVERNANCE_EXTERNAL_API_LOGGING_ENABLED=true

SAML_IDP_METADATA_URI=https://idp.example.com/metadata
SAML_SP_ENTITY_ID=https://portal.example.com/saml2/service-provider-metadata/knox
SAML_SP_ACS_LOCATION=https://portal.example.com/login/saml2/sso/knox
```

현재 systemd 예시는 `EnvironmentFile=/opt/governance-portal/config/governance-portal.env`로 env 파일을 분리한다.

Oracle DB 기본 JDBC 드라이버는 백엔드 JAR에 `ojdbc11` 런타임 의존성으로 포함한다. Autonomous Database처럼 Wallet 기반 접속을 쓰는 경우에는 Wallet 파일과 함께 `oraclepki`, `osdt_core`, `osdt_cert` 같은 Oracle security companion JAR가 추가로 필요한지 확인한다.

## 6. 빌드/업로드 묶음 기준

운영 반영 전 작업 PC에서 빌드한다.

```powershell
.\scripts\build-production.ps1
```

업로드 묶음 예시:

```text
governance-portal-release-YYYYMMDD-HHMM.zip
  frontend-dist/
    index.html
    assets/
  backend/
    governance-portal-backend.jar
  infra/
    nginx/governance-portal.conf
    systemd/governance-portal.service
  checksum.txt
  release-note.txt
```

운영 서버에는 압축 파일을 올린 뒤 임시 경로에서 해제하고, 검증 후 실제 경로로 반영한다.

```text
/tmp/governance-portal-release/
-> 검증
-> /var/www/governance-portal/
-> /opt/governance-portal/
```

## 7. 업로드 전 체크리스트

| 항목 | 확인 |
|---|---|
| 프론트 빌드 성공 | `npm run build` 또는 `build-production.ps1` 성공 |
| 백엔드 빌드 성공 | `bootJar` 성공 |
| 테스트 통과 | 백엔드/프론트 테스트 결과 확인 |
| 파일 크기 확인 | JAR와 dist가 정상 생성됐는지 확인 |
| 운영 env 분리 | 비밀번호, 인증서, SAML 값이 산출물에 포함되지 않았는지 확인 |
| Nginx 설정 확인 | `/api`, `/login`, `/saml2`, `/actuator` 프록시 누락 여부 확인 |
| systemd 설정 확인 | 실행 계정, JAR 경로, env 파일 경로 확인 |
| 롤백 파일 확보 | 이전 JAR/dist 보관 |

## 8. 서버 반영 후 확인 명령

```bash
sudo nginx -t
sudo systemctl daemon-reload
sudo systemctl restart governance-portal
sudo systemctl status governance-portal
curl http://127.0.0.1:18080/actuator/health
curl http://localhost/actuator/health
```

포트 확인:

```bash
ss -lntp | grep 18080
ss -lntp | grep ':80\|:443'
```

로그 확인:

```bash
journalctl -u governance-portal -f
tail -f /var/log/nginx/governance-portal.error.log
tail -f /var/log/nginx/governance-portal.access.log
```

## 9. 우선순위

처음 운영 세팅 시 반드시 챙길 것은 아래 순서다.

1. 배포 계정, SSH key, 접속 경로
2. Java 21, Nginx, firewalld, chrony, logrotate
3. 서버 디렉터리와 권한
4. JAR, frontend dist, Nginx conf, systemd service
5. 운영 env 파일
6. TLS 인증서와 SAML metadata
7. DB 접속 정보와 Oracle Wallet
8. 로그/백업/롤백 절차
